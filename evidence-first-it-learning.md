# Evidence-First IT Learning

This note explains how I balance structured training with hands-on lab work while building toward entry-level IT support roles.

## Core Approach

- Use structured coursework to cover fundamentals and fill gaps that show up in real job descriptions.
- Use home labs, ticket-style writeups, and GitHub repos as proof of practical troubleshooting ability.
- Prefer a few strong, readable projects over a long list of shallow repos or certificates without supporting evidence.

## Why I Work This Way

- Coursework helps with vocabulary, coverage, and confidence.
- Labs and documentation show how I actually approach a problem:
  - what I checked first
  - how I isolated the issue
  - what fixed it
  - how I would prevent it next time
- That evidence maps more directly to entry-level IT support work than passive completion alone.

## What Good Evidence Looks Like

- Ticket-style troubleshooting labs
- Small Windows and Active Directory workflows
- Networking and DNS validation work
- Public-safe architecture and operations notes

## Role Alignment

- For deskside and desktop support, I emphasize endpoint, printer, login, permissions, and deployment-style troubleshooting.
- For broader IT support roles, I also keep Windows, Linux, networking, and documentation fundamentals visible.

## Practical Rule

- I use training to support lab creation, not to delay it.
- As soon as a lab setup is stable enough to demonstrate a support task, I document it as evidence.
